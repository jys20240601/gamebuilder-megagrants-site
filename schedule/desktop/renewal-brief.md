# MyPlanner 전체 UI 디자인 리뉴얼 의뢰서

작성 기준: 2026년 10월 19일. Windows 데스크톱, 휴대폰 웹, Android 앱과 태블릿의 시각 체계와 사용 흐름을 함께 리뉴얼한다. 실제 기능을 유지하면서 오늘의 일정과 할 일, 진행하는 프로젝트를 빠르게 파악하고 편집할 수 있게 만드는 것이 목적이다.

PC 앱의 현재 화면 참고: https://anewbyeol.kr/schedule/desktop/ — 샘플 데이터로 촬영한 Windows 앱의 화면 모음이다. https://anewbyeol.kr/schedule/ 은 모바일 동반 페이지다. PC UI 검토에는 데스크톱 참고 화면을 기준으로 사용한다.

## Claude Design에 바로 전달할 요청

> MyPlanner의 전체 UI와 디자인을 리뉴얼해 주세요. 아래 기능과 사용자 선호를 유지하면서 정보 구조, 화면 배치, 타이포그래피, 색상, 컴포넌트를 재설계해 주세요. Windows용 대시보드와 휴대폰 및 태블릿 화면을 같은 제품으로 느낄 수 있게 연결해 주세요.
>
> 먼저 디자인 방향 두 가지와 대표 대시보드를 제안해 주세요. 방향을 고르면 월간·주간 일정, 목표, 프로젝트, 할 일, 메모, 상세·편집 패널, 설정과 알림 화면을 확장해 주세요. 한국어와 라이트 테마를 기준으로 만들고 다크 테마도 정의해 주세요.
>
> 실제로 조작할 수 있는 HTML/CSS/JavaScript 프로토타입과 디자인 토큰, 화면별 동작 명세를 주세요. 프로토타입은 샘플 데이터만 사용하고 실제 Google 로그인이나 서버 연결 없이 열리게 해 주세요. 달력 이벤트는 읽기 전용이며, 사용자가 작성하는 항목과 혼동되지 않아야 합니다.
>
> 보드에는 제목을 간결하게 표시하고, 본문은 선택한 항목의 상세 영역에서 읽게 해 주세요. PC의 조회·추가·편집은 오른쪽 인라인 패널을 기본으로 하고, 휴대폰은 현재 화면의 상세 페이지로 자연스럽게 이어지게 해 주세요. 기능을 임의로 제거하거나 새 기능을 이미 구현된 것처럼 표현하지 마세요.

## 제품과 사용 환경

제품 이름은 **MyPlanner**다. 내부 실행 파일·프로젝트 이름에는 OrcaCalendar가 남아 있지만 새 UI의 브랜드 표기는 MyPlanner로 통일한다.

| 환경 | 현재 역할 | 리뉴얼에서 다룰 내용 |
|---|---|---|
| Windows 데스크톱 | 바탕화면 대시보드, 월간·주간 일정, 목표·프로젝트·할 일·지식 관리 | 넓은 화면의 정보 배치, 보드, 오른쪽 상세·편집, 창 크기별 대응 |
| 휴대폰 웹 | 일정·할 일·목표·메모의 4개 기본 탭, 목표 안의 프로젝트 화면 | 빠른 확인과 입력, 목록·상세의 이동, 작은 화면의 가독성 |
| Android 앱 | 휴대폰 웹을 표시하고 Google 연결·브리핑·외부 알림을 제공 | 웹과 같은 본문 UI, 앱 전용 설정과 권한 상태 |
| Android 태블릿 | 같은 APK를 사용할 수 있음 | 세로·가로 레이아웃, 목록과 상세를 함께 보는 구성 제안 |

Android 태블릿은 실기기 검수가 남아 있다. Android 전용 알림 항목은 일반 브라우저에 그대로 노출하지 않는다. 데스크톱의 로컬 문서·폴더 연결 기능도 휴대폰에 동일하게 존재한다고 표현하지 않는다.

## 유지할 사용자 선호

- 기본은 밝고 읽기 쉬운 화면이다. 현재 Notion 계열의 차분한 레이아웃을 참고하되 구체적인 색과 형태는 새로 제안할 수 있다.
- 보드 카드에는 제목 중심으로 간결하게 표시한다. 긴 본문, 설명, 관계와 날짜는 상세 패널로 보낸다. 선택 상태와 완료 동작은 분명해야 한다.
- 상세 패널은 큰 볼드 제목, 굵은 소제목, 읽기 편한 본문으로 위계를 만든다. 제목·본문·보조 정보가 같은 크기와 굵기로 섞이지 않게 한다.
- 관리 화면은 세로 열을 기본으로 구성한다. 기간 필터와 상태 분류를 서로 다른 층으로 보여 준다.
- 조회·추가·편집은 같은 맥락 안에서 이어진다. PC에서 별도 팝업 창을 기본 편집 흐름으로 사용하지 않는다.
- 저장·취소는 긴 편집 화면에서도 접근할 수 있어야 한다. 편집 중 화면을 바꾸면 변경 내용을 보존하거나 명확하게 선택하게 한다.
- 주간 일정은 날짜 헤더를 유지한 채 내용 영역에서 스크롤한다. 카드와 클릭 영역이 바깥으로 넘치지 않게 한다.
- 동기화·권한 상태는 필요할 때 알아볼 수 있게 하되, 정상 상태에서 관리 문구가 화면을 차지하지 않게 한다.

## 데이터의 의미

| 항목 | 의미 | 화면에서 지켜야 할 점 |
|---|---|---|
| 목표 | 이루려는 결과 또는 생활 방향 | 최종 목표·5년 목표·1년 목표 그룹과 관련 내용을 표현 |
| 프로젝트 | 실제 업무와 산출물이 있는 구체적인 일 | 준비 중·진행 중을 중심으로 표시하고 목표·할 일과 연결 |
| 할 일 | 사용자가 실제로 수행할 행동 | 실행일과 마감일을 다른 필드로 표시 |
| 메모 | 사용자가 기록한 본문 | 제목·본문·날짜와 관련 항목을 읽고 편집 |
| 참고 자료 | 링크 또는 PC 문서·폴더 참조 | 메모와 구분하고, 지원 환경에 맞게 열기 동작 표시 |
| Google 일정 | Google Calendar에서 읽은 일정 | 상세 조회 및 Google Calendar 열기만 제공 |

**실행일(plannedDate)**은 그 일을 하기로 한 날이고, **마감일(dueDate)**은 실제 기한이다. 실행일을 지정했다고 마감 경고를 만들지 않는다. 개인 루틴은 날짜를 지정한 할 일로 표현할 수 있다.

목표나 프로젝트를 등록하지 않은 할 일도 정상적으로 존재한다. 모든 항목에 프로젝트 연결을 강제하지 않는다. 운동 같은 생활 방향은 개인 목표로, 날짜가 정해진 행동은 할 일로 표현한다.

샘플 제목도 주제부터 쓴다. 예: `월간 보고서 · 초안 작성`, `아침 운동 · 걷기 20분`. `할 일:`, `해야 할 일` 같은 긴 분류 접두어는 붙이지 않는다. 이 예시는 디자인용 가상 데이터다.

## 화면별 요구사항

### 대시보드

현재 구성은 사용자 지정 제목과 한 줄 문구, 시계, 7일 날짜 스트립, 오늘 일정·다가오는 마감·다가오는 일정 목록, 목표·프로젝트·할 일·일정·지식 관리 진입점, 월간·주간 달력이다. 각 영역의 크기와 위치는 새로 제안할 수 있다.

화면을 열었을 때 오늘 날짜, 곧 시작하는 일정, 실행할 일, 실제 마감이 우선순위에 맞게 보이게 한다. 시계는 끌 수 있어야 한다. 로컬 할 일과 Google 일정이 같은 달력에 표시될 때 출처와 열기 동작을 구분한다.

### 월간과 주간 일정

- 이전·오늘·다음, 월간·주간 전환, 선택한 날짜를 분명하게 표시한다.
- 종일·여러 날 일정, 시간 일정, 진행 중·지난 일정, 오늘, 주말, 실제 마감을 구분한다.
- 셀 안에 표시할 수 없는 일정은 `+N개` 등으로 이어서 확인하게 한다.
- 주간 내용은 고정된 날짜 헤더 아래에서 스크롤한다.
- Google 일정 상세에는 제목, 캘린더와 색, 시간, 장소, 설명과 허용된 링크를 표시한다. 수정은 `캘린더에서 관리하기`로 연결한다.

### 목표 관리

최종 목표·5년 목표·1년 목표를 세로 열로 보여 준다. 카드는 제목 중심이고, 선택한 목표의 원하는 결과·본문·분류·관련 항목은 상세 패널에서 읽는다. 긴 제목과 비어 있는 열도 설계한다.

### 프로젝트 관리

기본 보드는 **준비 중·진행 중** 두 열이다. 완료·보류·보관 항목은 별도 보관함으로 이동해 확인한다. 프로젝트 상세에는 관련 목표와 연결된 할 일을 보여 준다. 제목만으로 부족한 본문 정보는 오른쪽 상세에 표시한다.

### 할 일 관리

위에는 **오늘·내일·이번주·이번달·전체** 기간 탭을 두고 기본값은 전체다. 아래에는 **다음·예정·대기** 상태 열을 배치한다. 기간을 골랐을 때 날짜 없는 일도 포함할 수 있는 선택을 제공한다.

실행일이 있으면 내부 상태가 `next`여도 예정 열에 표시한다. 대기 상태는 실행일이 있어도 대기로 유지한다. 완료 항목은 별도 보관함으로 열고 인박스는 새 기본 화면에 만들지 않는다. 날짜 필터와 상태 열을 합쳐 하나의 분류로 만들지 않는다.

상세·편집에는 제목, 본문, 상태, 실행일, 마감일, 관련 프로젝트와 기타 지원되는 관계를 배치한다. 완료 처리와 단순 선택의 클릭 영역을 구분한다.

### 지식과 메모

PC의 지식 관리는 메모와 참고 자료를 구분한다. 제목 목록에서 선택하면 본문을 상세 영역에 표시한다. 긴 본문, 소제목, 목록, 강조, 줄바꿈을 읽기 쉽게 구성한다. 휴대폰에서는 메모를 빠르게 작성하고 저장 상태를 확인할 수 있게 한다.

메모와 목표·프로젝트·할 일은 기기 간 동기화되지만 PC 전용 참고 자료·로컬 링크까지 모두 동기화되는 것으로 표현하지 않는다.

### 설정과 연결 상태

설정은 외형·보기, 창 배치, Google 연결·동기화, Android 알림처럼 사용 목적별로 묶는다. 평소의 사용 화면에 OAuth 클라이언트 ID, 토큰, 내부 파일명 같은 구현 정보를 드러내지 않는다.

처음 연결, 연결됨, 일시적 오프라인, 동기화 중, 다시 연결 필요, 일부 권한 없음, 저장 실패 상태를 구분한다. 오프라인의 로컬 저장과 Google 동기화 완료를 같은 문구로 표현하지 않는다.

### Android 알림

정기 브리핑과 외부 알림은 서로 다른 기능이다. 정기 브리핑에는 켜기·간격·조용한 시간·최근 알림·테스트가 있고, 외부 알림에는 켜기·기기 등록·알림 권한·최근 수신·진동 방식이 있다.

외부 알림 진동 선택지는 **10초 반복 진동**과 **확인할 때까지 반복 진동**이다. 소리는 기본으로 사용하지 않는다. 사용자에게 저장된 방식과 권한 상태를 명확하게 보여 준다. 알림 창을 열거나 알림을 열기·지우기·진동 중지 동작으로 반복 진동이 멈출 수 있다는 설명이 필요하다. 알림 확인을 할 일 완료로 표시하지 않는다.

S24의 1.1.1 업데이트와 약 10초 진동의 정상 종료는 확인됐다. 확인할 때까지 반복 모드와 중지 동작은 실기기 검수가 남아 있다.

## 디자인 방향과 산출물

첫 제안은 차분한 플래너와 정보 밀도가 높은 업무 대시보드처럼 서로 비교할 수 있는 두 방향으로 보여 준다. 둘 다 가독성과 실제 사용 흐름을 우선하며, 특정 색·폰트·장식은 확정된 사용자 선호로 간주하지 않는다.

| 산출물 | 필요한 내용 |
|---|---|
| 대표 화면 | PC 대시보드, 할 일 보드와 상세 패널, 휴대폰 일정·할 일, 태블릿 목록·상세 |
| 전체 화면 | 월간·주간, 목표, 프로젝트, 할 일, 메모·참고 자료, 상세·추가·편집, 보관함, 설정 |
| 상태별 화면 | 비어 있음, 긴 제목·본문, 항목 많음, 선택됨, 편집 중, 저장 중·실패, 오프라인·재연결 |
| 디자인 토큰 | 색·타이포그래피·여백·선·모서리·아이콘·선택/비활성/오류 상태, 라이트·다크 대응 |
| 반응형 규칙 | PC 1920×1032와 1366×768, 작은 위젯 380px 폭, 휴대폰 390×844, 태블릿 800×1280와 1280×800 |
| 동작 가능한 프로토타입 | 화면 전환, 탭·필터, 카드 선택, 상세·편집, 보관함, 설정과 저장 상태 |
| 개발 전달 명세 | 영역 크기·간격, 타이포그래피, 컴포넌트별 상태, 스크롤·넘침·저장·뒤로 가기 동작 |

휴대폰은 화면 전체가 가로로 밀리지 않게 한다. 보드를 작은 화면에 적용할 때는 열 선택 탭 등으로 바꿀 수 있다. 태블릿에서는 넓이에 따라 목록과 상세를 함께 보여 주고 세로·가로 회전 규칙을 정의한다. 제시한 태블릿 크기는 디자인 검수용 가정이며 특정 기기의 실측 크기가 아니다.

PC 본문은 읽을 수 있는 크기를 확보하고, 모바일 본문은 16px 전후를 출발점으로 제안한다. 터치 조작은 약 44px 이상의 영역, 텍스트와 배경은 충분한 대비를 목표로 한다. 색만으로 완료·오류·선택을 구분하지 않는다.

## 개발 제약

Windows는 .NET Framework 4.8 WinForms와 GDI 직접 그리기다. HTML 프로토타입은 디자인 전달용이며 실제 제품을 웹 앱으로 교체하는 요구가 아니다. 단색·단순 그라데이션·둥근 사각형·선·간단한 SVG 경로·텍스트로 재현할 수 있는 구성이 적합하다. 블러·복잡한 그림자·상시 애니메이션을 핵심 표현으로 사용하지 않는다.

Windows 폰트는 Malgun Gothic·Segoe UI·Bahnschrift 등 설치된 폰트를 기준으로 한다. 다른 폰트를 제안하면 설치·배포 조건과 대체 폰트를 함께 적는다. 웹에만 사용할 수 있는 폰트 효과를 PC 구현의 필수 조건으로 만들지 않는다.

Google Calendar의 읽기 전용 권한, Drive의 제한된 접근, 기존 항목 ID와 동기화 형식은 유지한다. UI 리뉴얼을 이유로 데이터를 삭제·재생성하거나 OAuth 권한을 확대하지 않는다. 바탕화면 모드, 시계 끄기, 창 크기 변경과 저부하의 이벤트 기반 렌더링도 유지한다.

## 완료 판단

- 처음 보는 사람이 Google 일정과 직접 작성한 할 일을 구분할 수 있다.
- 기본 보드에서 항목을 빠르게 훑고 선택한 본문을 편하게 읽을 수 있다.
- 목표·프로젝트·할 일의 의미와 실행일·마감일의 차이가 유지된다.
- 긴 주간 일정과 편집 폼에서도 헤더·저장 동작에 접근할 수 있다.
- 휴대폰 가로 넘침과 PC·태블릿의 과도한 빈 공간을 해결한다.
- 라이트·다크, 작은 창, 빈 목록, 오류 상태를 같은 컴포넌트 체계로 설명할 수 있다.

## 현재 구현을 참고할 파일

저장소 루트의 `AGENTS.md`와 `HANDOFF.md`가 현재 기능과 사용자 선호의 기준이다. PC 화면은 `src/App/WidgetView.Home.cs`, `WidgetView.Calendar.cs`, `WidgetView.Space.cs`, `WorkspacePane.cs`에 있으며 휴대폰 화면은 `web/schedule/index.html`, `app.css`, `app.js`에 있다. Android 전용 기능은 `android/README.md`와 `android/BRIDGE.md`를 참고한다.

기존 `design/DESIGN_BRIEF.md`, `orca-calendar-current.html`, `design/screenshots/`는 초기 디자인 참고 자료다. 현재의 관리 기능·라이트 기본·인라인 편집 요구와 다른 설명이 있으므로 기능 기준은 이 리뉴얼 의뢰서를 따른다. 별도 실제 화면을 첨부할 때도 초기 시안과 현재 구현을 구분해서 표시한다.
