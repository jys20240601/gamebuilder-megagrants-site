디지털트윈 인터뷰 노트목차

정제, 정합, DB 저장은 어떻게 하나

개념은 02 디지털트윈 빅데이터가공, MQTT는 04 MQTT 참고.

어디서 하나

MQTT를 구독한 Python 저장기 안에서, 메시지 한 통이 올 때마다 아래 순서로 처리한다(실시간). 밤에는 하루치를 다시 검사하고 집계한다(배치).

받기 → ⓪ 원본 보관 → ① 정제 → ② 정합 → ③ DB 저장 → ④ 조회(언리얼·분석)

① 정제: 검사하고, 고치고, 표시하고, 버린다

문제 규칙 처리
형식 오류 (JSON 잘림, 필수 칸 없음) JSON이 풀리는가, device·value·time이 있는가 버림, 원본과 오류 기록만 남김
범위 밖 (온도 999) 물리적으로 가능한 범위(예: -20~120℃) out_of_range 표시
튀는 값 (1초 만에 32 → 85) 직전 정상값과 차이가 기준(예: 5℃)을 넘는가 spike 표시 (지우지 않음)
중복 (QoS 1 재전송) 같은 장비·시각·값 하나만 남김
단위 섞임 (화씨 장비) 장비 대장의 단위 ℃로 변환
시계 틀림 (장비 시각이 2분 늦음) 수신 시각과 차이가 허용치(예: 5초)를 넘는가 수신 시각 사용, clock_fixed 표시
누락 (값이 안 옴) 기대 주기 안에 값이 있는가 짧으면 앞뒤 보간, 길면 "끊김" 표시

② 정합: 같은 대상, 같은 시간, 같은 좌표

  • 장비 대장이 중심이다. 센서 ID, 3D 물체(언리얼 액터) 이름, 보내는 단위, 정상 범위, 최대 변화량, 설치 위치를 한 표에 둔다.
센서 ID 언리얼 액터 단위 정상 범위 1초 최대 변화
pump03 BP_Pump_03 C -20~120 5
pump05 BP_Pump_05 F -20~120(℃ 기준) 5
crane07 BP_Crane_07 위경도 터미널 구역 안 이동 5m
  • 대상: 메시지의 device로 대장을 찾아 액터 이름을 붙인다. 대장에 없으면 보류 표로 보내고 담당자에게 알린다.
  • 시간: 모두 UTC로 저장한다. 10:00:00+09:00 → 01:00:00Z. 주기가 다른 데이터(1초 5회, 1초 2회)는 1초 칸으로 다시 나눠 같은 순간끼리 나란히 놓는다.
  • 좌표: 위경도 35.10560, 129.08200 → 터미널 원점 35.10500, 129.08000 기준 동쪽 182.3m, 북쪽 66.6m → 언리얼 cm 18,230 · 6,660. 실제로는 pyproj나 언리얼 Georeferencing이 계산하고, 축 방향은 Georeferencing 설정을 따른다.

③ DB 저장

시각 · 무엇 · 값 세 칸에 품질 표시를 더한 형태가 시계열 DB의 기본이다.

-- PostgreSQL + TimescaleDB 예
CREATE TABLE sensor_data (
  time      TIMESTAMPTZ NOT NULL,  -- 측정 시각(UTC)
  asset_id  TEXT NOT NULL,         -- 3D 물체와 연결되는 ID
  metric    TEXT NOT NULL,         -- temp, east_m ...
  value     DOUBLE PRECISION,
  quality   TEXT                   -- ok, spike, clock_fixed ...
);
SELECT create_hypertable('sensor_data', 'time');  -- 시간순 대용량 저장용으로 지정

InfluxDB를 쓰면 같은 내용을 measurement(표 이름), tag(asset_id 같은 구분), field(값)로 나눠 적는다.

저장 위치 무엇 용도
최신값 메모리 캐시, MQTT Retained 지금 화면
이력 시계열 DB 그래프, 재생, 분석
원본 받은 그대로의 파일(JSON 줄 묶음, Parquet) 규칙을 바꿔 다시 정제

④ 조회

-- 지난 1시간, 장비별 1분 평균(정상값만)
SELECT time_bucket('1 minute', time) AS minute, asset_id, avg(value)
FROM sensor_data
WHERE metric = 'temp' AND quality = 'ok' AND time > now() - interval '1 hour'
GROUP BY minute, asset_id;

-- 사고 시각 10분 재생(언리얼 타임라인용)
SELECT * FROM sensor_data
WHERE time BETWEEN '2026-11-15 01:00:00Z' AND '2026-11-15 01:10:00Z'
ORDER BY time;

데이터가 쌓이면 보관 규칙을 정한다. 예: 1초 원값은 30일, 1분 평균은 1년.

저장기 코드 뼈대 (Python)

def on_message(client, userdata, msg):
    raw = msg.payload.decode()
    save_raw(raw)                                   # ⓪ 원본 그대로 보관
    try:
        d = json.loads(raw)                         # ① 형식 검사
    except ValueError:
        return log_error(raw)
    asset = REGISTRY.get(d.get("device"))           # ② 대상 정합: 센서 → 3D 물체
    if asset is None:
        return hold_unknown(d)
    v = to_celsius(d["value"], asset.unit)          # ① 단위 통일
    t = fix_time(d["time"], received_at=now_utc())  # ② 시간 정합(UTC, 시계 보정)
    if is_duplicate(asset.id, t, v):                # ① 중복 제거
        return
    q = "ok"
    if not asset.min <= v <= asset.max:
        q = "out_of_range"
    elif abs(v - last_ok[asset.id]) > asset.max_jump:
        q = "spike"
    db.insert(t, asset.id, "temp", v, q)            # ③ 저장
    if q == "ok":
        last_ok[asset.id] = v

다섯 가지 원칙 (인터뷰용)

  1. 원본은 지우지 않는다. 규칙을 바꾸면 원본으로 다시 정제한다.
  2. 지우기보다 표시한다. quality 칸에 표시하고 분석할 때 걸러 쓴다.
  3. 시간은 UTC로 저장한다. 한국 시간은 화면에서만 바꾼다.
  4. 장비 대장이 정합의 중심이다.
  5. 규칙은 코드가 아니라 표로 관리한다. 장비를 추가할 때 대장에 한 줄만 넣으면 된다.
