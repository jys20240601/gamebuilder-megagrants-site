디지털트윈 인터뷰 노트목차

디지털트윈을 위한 빅데이터 가공

01 삼우이머션 파악의 다음 단계. 과정의 핵심을 "디지털트윈 + 그것을 움직이는 빅데이터 가공"으로 보고 정리했다.

0. 한 문장으로

디지털트윈의 빅데이터 가공은 현장에서 쏟아지는 서로 다른 데이터를 같은 좌표, 같은 시간, 같은 대상으로 맞추고, 실시간 3D가 감당할 양으로 줄여서 트윈에 흘려보내는 일이다.

일반 빅데이터 과정과 다른 점:

일반 빅데이터 분석 디지털트윈의 빅데이터
결과물 보고서, 대시보드, 모델 실시간으로 움직이는 3D 현장
시간 지난 데이터를 모아 분석(배치) 지금 데이터를 바로 반영(스트림) + 이력 분석
데이터 주로 표 데이터 표 + 공간(좌표, 3D) + 영상
가장 어려운 일 분석 모델 정합: 센서 값이 3D 화면의 어느 물체, 어느 위치, 어느 시점인지 맞추기

심사에서는 "3D는 마지막 표현층이고, 그 앞의 수집·정제·정합·적재·처리·분석이 모두 빅데이터 작업"이라고 말하면 디지털트윈 과정을 빅데이터 과정으로 설명할 수 있다.

1. 디지털트윈에 들어오는 데이터 5종 (+ 역방향 1종)

종류 예 특성 삼우이머션 사례 가공 포인트
공간 데이터 (정적) DEM 지형, 항공사진, 포인트 클라우드, CityGML·shapefile, CAD/BIM, 전자해도 용량이 크고 좌표계가 제각각 자갈치(CityGML, shapefile, DEM, 포인트 클라우드 리토폴로지), 터미널(DEM, 전자해도 S-63) 좌표계 통일, 경량화(LOD, 3D Tiles, Nanite), 객체마다 ID 붙이기
센서 시계열 (동적) 온도, 진동, 수질, 공기질, 화재, 전력 빈도가 높고 끊기거나 튀는 값이 섞임 자갈치(해수 수질, 침수, 유해가스, 화재), 한화오션(온도, 강도, 피로) 결측·이상치 처리, 리샘플링, 단위 통일, 임계값 판정, 집계
위치 궤적 장비 GPS, 작업자 헬멧·워치, 선박 AIS, 레이더 시간 + 좌표. 양이 가장 빨리 커짐 터미널(장비 1초 5회 ±10cm, 헬멧 1초 2회 ±1m), 해상공사(AIS·레이더), 부산대 PoC(대용량 AIS/GPS) 좌표 변환, 튀는 점 제거, 화면용 보간, 궤적 압축, 정박·운항 구분
영상 CCTV 원본은 트윈에 넣기에 너무 큼 터미널(번호 인식, 트럭 대기열), 해상공사(딥러닝 선박 인식) 영상을 AI로 이벤트 데이터(무엇이, 어디서, 언제)로 바꿔서 넣음
운영·업무 데이터 작업 지시, 선적 계획, 설비 사양, 문서 다른 시스템(DB, ERP)에 있음 터미널 운영 데이터, 한화오션(사양, PDF 문서 뷰어) 센서·위치 데이터와 조인(장비 ID, 시간 기준)
합성 데이터 (역방향) 트윈에서 렌더링한 이미지와 자동 라벨 트윈이 데이터를 만들어 냄 해상공사 선박 인식 학습 데이터 증강(각도, 색감, 좌우반전) 밤·비·안개 같은 조건을 바꿔 AI 학습 데이터 생성(도메인 랜덤화)

2. 가공 파이프라인 7단계

단계 하는 일 디지털트윈에서 특히 중요한 점 도구 예
① 수집 센서, 장비, 외부 API, 파일에서 데이터를 받음 프로토콜이 파편화돼 있다. 신규 장비는 MQTT, 옛 설비는 Modbus·OPC UA, 외부는 REST API. 그래서 엣지 서버에서 한 번 모은다(자갈치) MQTT 브로커(Mosquitto 등), oneM2M, Python 수집기
② 정제 결측, 이상치, 중복, 시간 오류 처리 센서가 끊기면 트윈 속 물체가 멈추거나 순간이동한다. 화면에 바로 보이는 품질 문제다 Python(pandas), 필터(이동평균, 칼만 필터)
③ 정합 공간, 시간, 대상을 맞춤 디지털트윈 특유의 핵심 단계. 아래 2-1 참고 pyproj(좌표 변환), UE Georeferencing, Cesium, ID 매핑 테이블
④ 적재 용도별로 저장 실시간(최신값), 이력(시계열), 원본 보관을 나눈다 최신값 캐시(Redis 등), 시계열 DB(InfluxDB, TimescaleDB 등), 원본 파일(Parquet, 오브젝트 스토리지)
⑤ 처리 스트림 집계, 배치 집계, 이벤트 판정 "1분 평균 진동이 기준치를 넘으면 알람"처럼 시간 창 단위로 계산해 이벤트를 만든다 스트림 처리(Kafka 계열), SQL 집계, 룰 엔진
⑥ 분석·AI 이상탐지, 고장·생산성 예측, 충돌 위험, 비전 인식 결과를 다시 트윈에 표시(위험 장비를 빨갛게, 예측 경로를 선으로) scikit-learn, 시계열 예측 모델, YOLO류 비전
⑦ 전달·시각화 트윈이 받을 수 있는 형태로 보냄 데이터 주기와 화면 주기가 다르다. 아래 2-2 참고 UE MQTT 플러그인, WebSocket, REST, UMG 차트, 머티리얼 파라미터

2-1. 정합: 세 가지를 맞춘다

  1. 공간 정합 (좌표) - 한국 공간 데이터는 좌표계가 섞여 있다. EPSG:4326(WGS84 경위도, GPS·AIS), EPSG:5186(국토지리정보원 표준 중부원점 TM), EPSG:5179(UTM-K) 등이다. - 언리얼은 cm 단위 직교 좌표를 쓴다. 그래서 "원본 좌표계 → WGS84 → 언리얼 원점 기준 로컬 좌표"로 바꾼다. 삼우이머션도 지오레퍼런싱 플러그인으로 여러 좌표계를 WGS84로 통일했다. - 넓은 지역은 3D Tiles로 바꿔 Cesium for Unreal로 스트리밍한다. 국내 도구 mago 3DTiler는 -crs 5186처럼 원본 좌표계를 지정해 3D Tiles로 변환한다. - 원점에서 멀어지면 부동소수점 오차로 물체가 떨린다. 원점 재설정(Large World Coordinates)이 필요한 이유다.
  2. 시간 정합 (동기화) - 센서마다 시계가 다르고 보내는 주기도 다르다(장비 1초 5회, 헬멧 1초 2회, AIS 수 초~수 분). - 모든 데이터를 같은 기준 시간(UTC 등)으로 맞추고, 같은 시간 격자로 리샘플링해야 "그 순간의 현장"을 재현하고 되돌려 볼 수 있다(재생 기능).
  3. 대상 정합 (ID 매핑) - "센서 TEMP-0231"이 3D 화면의 "3번 펌프"라는 사실을 매핑 테이블로 관리한다. - 이 테이블이 없으면 데이터와 3D가 따로 논다. 실무에서 시간이 가장 많이 드는 부분이다.

2-2. 트윈으로 보내기 전에 줄이기

  • 보간: 데이터는 1초 5회 오는데 화면은 1초 60프레임이다. 그 사이를 보간해서 부드럽게 움직인다. AIS처럼 드문 데이터는 속도·침로로 위치를 추정한다(추측 항법).
  • 변경분만 전송: 값이 바뀐 것만 보낸다.
  • 데이터 LOD: 멀리서는 구역별 평균·히트맵, 가까이 가면 개별 센서 원값을 보여 준다.
  • 이벤트 우선: 원본 영상 대신 "트럭 대기열 12대" 같은 이벤트만 보낸다.

3. 사례로 처음부터 끝까지: 부산항 터미널

인터뷰에서 1분 안에 말할 수 있게 연습할 예시다.

  1. 수집: 항만 장비 GPS가 1초에 5번 위치를 MQTT로 보낸다. 작업자 스마트 헬멧은 1초에 2번 위치와 생체신호를 보낸다. CCTV는 컨테이너 번호와 트럭 대기열을 인식한다.
  2. 규모: 장비 1대가 하루에 432,000건(5 × 86,400초)을 만든다. 장비 100대라면 하루 4,320만 건이다. 여기에 헬멧과 CCTV 이벤트가 더해진다. 이것이 디지털트윈 빅데이터의 규모 감각이다.
  3. 정제: ±10cm 오차를 넘어 튀는 점을 걸러내고, 끊긴 구간을 표시한다.
  4. 정합: WGS84 좌표를 언리얼 좌표로 바꾸고, 장비 ID를 3D 크레인·차량 액터에 연결하고, 모든 시각을 하나의 기준 시간으로 맞춘다.
  5. 적재: 최신 위치는 캐시, 이동 이력은 시계열 DB, 원본은 파일로 보관한다.
  6. 처리: 작업자와 장비 거리가 기준보다 가까우면 위험 알람을 낸다. 시간대별 크레인 작업량을 집계한다.
  7. 분석: 작업량 이력으로 생산성을 예측한다. 이상 진동으로 고장을 미리 진단한다.
  8. 시각화: 언리얼에서 장비가 보간되어 움직이고, 위험 구역은 빨갛게, 대기열은 숫자로 보인다. 지난 시간을 되돌려 보며 동선을 검증한다.

해양 쪽은 AIS로 같은 흐름을 만들 수 있다. AIS·레이더 위치 → 좌표 정합 → 충돌 위험 계산 → CCTV 영상 위 AR 표시(해상공사 안전 모니터링).

4. 과정에 녹이는 방법

4-1. 6월 설계안 Stage에 데이터 가공을 짝짓기

Stage 데이터 규모 배우는 가공 단계

4-2. 실습 데이터를 어디서 구하나

출처 내용 확인된 조건
공공데이터포털 "해양수산부_선박 AIS 동적정보" 지정 해역의 선박 경로·위치 2018-09 ~ 2023-03, 선박 식별번호(MMSI)는 가려서 제공, 이용 제한 없음
브이월드(국토교통부) 3D 지도와 공간정보 오픈 API 회원가입과 인증키 필요. 3D 형식은 glb, gltf, 3D Tiles 등. 3D 건물 API는 2019-07 보안 정책으로 중단된 이력이 있어 현재 제공 범위는 확인 필요
참여기업 실데이터 삼우이머션 현장 데이터 비식별·보안 처리 범위를 기업과 협의해야 함
직접 생성 교육용 센서 키트, 시뮬레이터, ROS2 로봇 데이터 생성부터 가공까지 전 과정을 통제할 수 있음
트윈이 만든 합성 데이터 언리얼 렌더링 + 자동 라벨 비전 AI 학습용

4-3. NCS "빅데이터플랫폼구축" 능력단위와의 대응

KDT 빅데이터 분야로 심사받는다면 이 표가 근거가 된다. 능력단위 이름은 채용 직무설명서·직업정보 사이트 같은 2차 자료 기준이고, ncs.go.kr 공식 확인은 아직 하지 않았다.

능력단위 우리 과정에서
빅데이터 플랫폼 요구사항 분석 캡스톤 기획서(참여기업 요구 분석)

빅데이터 처리시스템 개발 (2001020905_19v2) 실시간·이벤트 처리(알람), 정합
빅데이터 분석시스템 개발 이상탐지·예측 모델

5. 빅데이터 관점 예상 질문

질문 답변 포인트
디지털트윈 과정이 왜 빅데이터 과정인가? 트윈은 데이터 파이프라인의 끝에 붙은 화면이다. 7단계 중 앞의 6단계가 수집·정제·정합·적재·처리·분석이다. NCS 빅데이터플랫폼구축 능력단위와 대응된다
실제로 "빅" 데이터를 다루나? 장비 100대가 1초 5회면 하루 4,320만 건이다. 공공 AIS는 수년치 선박 궤적이다. 규모를 키운 부하 테스트를 실습에 넣는다
데이터는 어디서 구하나? 공공데이터(AIS, 브이월드), 참여기업 비식별 데이터, 직접 만든 센서·로봇 데이터, 트윈이 만든 합성 데이터
Hadoop·Spark 같은 분산처리는? 실시간 트윈의 중심은 스트림 처리와 시계열 DB다. 대량 이력 분석은 배치 처리로 다루되, 범위는 최종 커리큘럼에 맞춰 답한다
일반 빅데이터 과정과 무엇이 다른가? 공간·시간·대상 정합을 다룬다. 결과물이 보고서가 아니라 실시간으로 움직이는 현장이라, 데이터 품질 문제가 화면에 바로 드러난다
데이터 보안은? AIS 식별번호 비식별화, 항만·국가시설 공간정보 보안(3D 건물 API 중단 사례), 기업 데이터 반출 범위 협의
AI는 어디에 쓰나? 두 방향이다. 트윈 안에서 이상탐지·예측·비전, 트윈으로 합성 학습 데이터 생성. 여기에 AI 보조 코딩으로 개발 속도를 높인다

6. 오늘 공부 순서 (2~3시간)

  1. 0장의 한 문장과 2장의 7단계 표를 보지 않고 말해 본다.
  2. 2-1의 정합 세 가지(공간, 시간, 대상)를 예시와 함께 설명해 본다.
  3. 3장 부산항 사례를 1분 안에 처음부터 끝까지 말해 본다. 432,000건 계산을 외운다.
  4. 용어를 확인한다: MQTT(브로커, 토픽, 발행/구독, QoS), 시계열 DB, EPSG:4326·5186, 3D Tiles, 보간과 추측 항법.
  5. 5장 질문 7개를 소리 내어 답해 본다.
